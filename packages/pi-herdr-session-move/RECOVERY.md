# 恢复未完成的会话搬迁

适用于 `/session-move` 或 `herdr_session_move` 报错、超时、trust 阻塞，以及成功通知与现场不符。

先保全两端会话、草稿和记录，再选择唯一一端继续。不要同时继续两个副本，不手工补写握手标记，也不要先删除失败副本。

## 1. 定位本次记录

从错误中取得记录目录；默认位于 `$PI_CODING_AGENT_DIR/session-moves/`，未设置该变量时在 `~/.pi/agent/session-moves/`。读取 `move.json`，记下 `backend`、`sourcePane`、`sourcePid`、`sourceSessionFile`、`targetPane`、`targetSessionFile` 和目标 `cwd`。`sourcePane` / `targetPane` 在 Core 中保存 `t…` 地址，在旧 TUI 中保存 pane ID。

这些身份必须与本次请求匹配。没有 `move.json`、记录损坏或无法确定哪次请求时，保留源端；Core 用 `hc ls` 核实可能已创建的终端，旧 TUI 核实 workspace/pane。Core 启动目标与发布记录之间可能中断，此时目标不会自动续跑。仍不确定就报告记录路径与原错误，停止自动重试。

## 2. 核对记录与现场

| 标记             | 能证明什么                                                      |
| ---------------- | --------------------------------------------------------------- |
| `ready.json`     | 写入时，目标 Pi 已确认指定会话；其中 `pid` 是候选目标进程       |
| `committed.json` | 源端同意交接，不代表源 Pi 已退出                                |
| `completed.json` | 接收端已通过源 PID 退出和上下文检查；后续检查仍可能阻止自动续跑 |
| `cancelled.json` | 此次交接已取消；它可以与 `committed.json` 同时存在，按取消处理  |

按记录的运行时核对现场：Core 使用 `hc get <terminal>` 检查两端地址、live/finished、`foreground.pid` 和 cwd；旧 TUI 使用 `herdr agent get` 和 `herdr pane process-info`。同时检查原 `sourcePid` 是否仍存在。终端内程序或 PID 已变化时，把新 occupant 当作无关进程保留；标记不能替代当前身份检查。

将两端分别判为“本次 Pi 仍在”“本次 Pi 已退出”或“无法确认”。任何一端无法确认时，停在诊断，不启动另一份任务。

## 3. 选择继续位置

| 现场                                 | 下一步                                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------------------- |
| 源 Pi 仍在，已有取消/失败/超时提示   | 留在源端，保留其新消息和草稿；目标副本不作为最新工作依据                               |
| 源 Pi 仍在，尚无失败提示，目标仍等待 | 等本次交接的明确结果；已有 commit 也须等源端退出，持续阻塞则报告现场，不另起迁移       |
| 源 Pi 已退出，目标身份和上下文匹配   | 在目标端继续；已有任务或结果就沿用，避免重复发送继续指令。仍在交接等待时，先等明确结果 |
| 两端本次 Pi 都已退出                 | 对照两份会话的末尾记录，选择包含最新工作的文件，按下面方式恢复；无法判断时交给用户选择 |

手动恢复使用 Pi 原生会话入口，不携带内部握手参数：

```sh
pi --session /绝对路径/选中的会话.jsonl
```

若所选会话记录的 cwd 已不存在，先进入一个确认过的现存工作目录，再用 `pi --fork /绝对路径/选中的会话.jsonl` 生成副本，保留原文件。

手动恢复后，先核对 cwd、当前树分支和末尾任务，确认草稿已保全，另一端没有在执行同一任务，再继续工作。

## 4. 需要重新迁移时

先保存候选目标 Pi 中新增的输入或结果，再正常退出这次创建且身份匹配的候选 Pi。确认它已退出、源端无未处理草稿和排队消息后，才从源端发起一次新的迁移；旧记录和副本留作恢复依据。

再次发起前，上一轮候选进程必须已退出，源端工作已保全，且没有身份不明或仍在续跑的旧尝试。

正常调用和迁移范围见[使用说明](README.md#使用)。
