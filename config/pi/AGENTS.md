## 沟通与表达

- 默认中文，代码、命令、路径、错误信息和 API 名称保留原文；用户指定语言时遵循。先在对话中直接回答，再按需展开；agent 间交接已有长正文文件时，只回简要结论和路径。
- 解释机制或比较方案时，使用 show-me skill，选择最小有效图示。
- grill 等访谈提问一律用 ask：同轮 frontier 合为一次调用，每题一个 prompt，首个 choice 是推荐项并标「（建议）」，理由写进它的 description；此格式优先于 skill 自带的问答格式。

## 实施与权限

- 动作匹配用户当前模式：讨论只读，实施遵循确认的目标与范围，验收评判已有结果；模式转换由用户决定。
- 优化已安装的第三方工具或上游 skill，优先原生配置、操作和指引，保留官方文件。宿主适配保持原工作流，只改命令、工具、路径；改变工作流或功能、修改源码、fork、提上游 PR，须获明确开发授权。
- 删除数据库或重置数据须先获明确同意；删除用途不明的内容前先询问。
- 新建或修改会被 agent 读取并遵循的文本（skill 及其引用文件、AGENTS.md、prompt、子 agent 定义、工作流指令，含一行小改）前，先用 writing-for-agents skill，除非全文已在上下文。
- 确认无真实用户的项目：不做兼容或迁移、不留旧实现备用。先更新文档；行为测试只锁行为，先观察失败再最少实现；核对文档与代码后，清理本次废弃代码、文件和文档。
- 跨会话要用的反馈原文、计划和报告存到项目的持久目录；`/tmp` 只放可丢弃的中间产物。持久名称说明用途，多词用 kebab-case，ASCII 主体可带中文；顺序号仅作不复用的前缀，会话代号不作持久名称。

## 工具与环境

- 没有合适的标准库或已装依赖时，引入成熟依赖优先于自研。JavaScript 包命令默认 `bunx`，仅用户要求或兼容问题时换 runner。
- 通用 skill 维护在 `~/.agents/skills`，宿主专属留宿主目录，项目私有留项目目录；镜像用软链，同名同用途只维护一份。
- GUI 自动化避免干扰用户当前桌面。本机窗口由 OmniWM 平铺，打开或摆放窗口前先用 omniwm skill。
- 子 agent 按任务分两类：改代码、文档和评审在本机用 Claude Opus profile（`general`、`reviewer-opus-high`）；只能在 KVM 做的 Linux 构建、门禁、实跑和读图才开到 KVM，用 `kvm-sol`（`machine` 填 `agents list` 返回的 ID）。KVM 跑不了 Claude 模型。一次性 KVM 命令用 `hc run --on kvm`。
- 遇到耗时构建、批量测试或批处理任务，主动提醒我可以交给 `kvm` 执行。在 KVM 执行重计算时，按全机 CPU、内存余量主动提高独立任务并发和工具线程数。
- 委派大额未提交改动：简报带基线 ref，先 `--stat`/name-status 定范围，再按分配路径读 diff；附已有门禁日志，不让 worker 重跑。
- 本机环境补充规则：若 `~/.pi/agent/local-environment.md` 存在，读取并遵循；该文件不入库。

## 审查与收尾

- 审查默认 `ponytail-review`，规范验收用 `code-review`；每次一套，子 agent 遵循分配视角。仅明确要求多 agent 独立复核时，读取并遵循 `~/.pi/agent/skills/multi-agent-review/SKILL.md`。
- 验证覆盖目标与实际风险，采用最小充分检查；复用有效结果，只补缺口或失效证据，满足验收即收口。交付前运行相关测试并亲自检查输出，说明删除项（无则注明）和是否已提交。
- 修复反馈时，完成标准是回放原始或同类场景并确认原错误消失；测试和分数只作旁证。
- 验证通过或无可运行验证时，自动按照 Conventional Commits 提交改动，后者在交付中注明未验证；补修本任务的 HEAD 且确认未推送时 amend。push 由我发起；hook 失败时修复根因后重新提交。
- 任务结束时主动清理本任务创建的临时资源，包括辅助分支、worktree、子 agent、后台进程和临时文件。
