# Core 恢复细节

## keep 后只剩 shell

`hc keep` 在程序意外丢失后提供 shell，不会自动重新运行 agent 或旧任务。结合当前终端的状态、前台程序、保存会话标签及丢失记录判断；保留了会话路径只说明有恢复线索。

用 `hc get <终端>` 读取终端元数据；agent 的列举、读取、启动和消息操作仍走宿主允许的工具。机器身份与终端 ID 一起定位对象，远端与本机的同名终端不能互换。

原启动参数已变成 shell 时，通过宿主的会话索引与读取接口取得活动分支的有效设置，配置来源补充启动参数。配置型 worker 启动器可能附带角色、模型、共享上下文或监控绑定；加载旧历史后这些启动属性仍可能生效。逐项证明与基线一致，缺项报告未知。

## 窗口正式绑定

从当前 `herdr-app ls` 读取 space、tab、pane 与 terminal 的实际关系。`terminal.show` 是临时显示另一个终端，不会把该 pane 的原终端身份替换掉。

正式接入方式从当前 `herdr-app --skill` 和 `herdr-app commands` 选择。接入后再次读取窗口树：原 tab 中的实际终端应等于恢复映射的目标，程序应被识别为预期 agent；检查多 pane 的次序及是否出现重复入口。恢复前后的 focus 按用户最后选择保留。

## 关注状态迁移

先确认所用布局或宿主当前采用的标记格式与存储位置；以下是已见格式的解释，不替代当前实现：

| 标记                  | 迁移要求                                                           |
| --------------------- | ------------------------------------------------------------------ |
| `snoozed=<wake ms>`   | 保留原唤醒时间；已到期时按当前布局的 Woke 语义处理                 |
| `settled=<ms>:<turn>` | 保留 Settle 时间，将轮次对齐新终端的当前轮次，使后续新工作正常唤回 |
| `herdr.seen`          | 按新终端轮次映射已读关系，不能直接复制旧终端的大轮次               |
| 置顶及其顺序          | 按旧会话到新终端映射更新原存储；保留其间用户新增或取消的置顶       |

标记写入前后都重读当前状态。若新任务已开始、用户已改标记或对象身份变化，保留新状态并记录差异，避免恢复过程把真实工作重新收起。关注状态正确不代表父子关系正确，两者分别验收。

## 关闭影响

区分窗口关闭、pane 关闭、agent 退出和终端结束；查当前原生契约及对象的存活策略。父子关系、关闭路径和 `outlive_parent` 共同决定实际影响，仅凭 `keep` 或“窗口还在”不能作出保证。

据证据说明哪些进程会退出、哪些继续运行、哪些入口会消失。契约不足时明确未验证，保留工作会话；需要实验时使用独立测试环境。关闭恢复者不会自动把错误父子关系改回原关系。
