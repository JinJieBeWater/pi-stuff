# Herdr Session Recovery

以原会话身份恢复到交互待命；继续旧任务按用户的单独指令执行。Herdr 拥有进程和窗口，执行入口遵循当前宿主的工具边界。

## 恢复流程

1. **留存基线。** 读取 `hc --skill`、`herdr-app --skill` 和宿主 agent 工具的 help；使用当前安装版本的接口。查询目标机器、现有 agent、保存会话及窗口位置，按“机器身份 + 保存会话身份”建立恢复清单：
   - 原会话 ID 或规范保存路径、旧终端 ID、父会话、顶层或 worker 角色。
   - 有效模型、思考档、目录、必要的启动参数或配置来源。
   - 原 space、tab、pane、名称、存活策略。
   - Snoozed 唤醒时间、Settled 时间与轮次、置顶、未读状态及其他已存在的关注状态。

   按宿主的持久记录约定保存清单、来源和采集时间，凭据与完整环境变量留在原配置中。仍运行的会话标为复用；未指定恢复的正常结束会话和普通 shell 留在原状；远端不可达标为未知。缺失信息先查会话索引与持久记录，仅对会改变恢复动作的歧义询问用户。**每个目标均有唯一匹配或明确阻断后进入下一步。**

2. **核验恢复能力。** 选择能保留基线身份、角色、模型和父子关系的原生恢复入口，核对其启动后行为及窗口接入方式。代理工具若只提供创建新 worker 的能力，`spawn` 后加载旧历史不能作为主会话恢复方案；保留现状，报告该分支缺少的能力和已确认的可用入口。模型、思考档或角色需要替代时，先说明差异并取得对应授权。源码、布局修改另属开发任务。

3. **先验一组。** 从清单选首个待恢复主会话及其子会话；只有主会话时先验一个。先父后子，记录旧会话到新终端的映射，执行第 6 步的全部检查。顶层会话仍为顶层；子会话指向原父会话对应的新终端，不能统一挂到执行恢复的会话。临时借显、shell 存活或启动请求成功均不足以通过验收。**样本全部通过后才扩大恢复。**

4. **按依赖恢复。** 复用样本结果；独立分支可并行，每个分支先父后子。每次启动前重查是否已有同会话的存活实例，返回不确定时先查实际结果再重试。逐项记录复用、恢复、跳过和阻断；任一身份或关系检查失败，暂停该分支的后续启动。用户已重新开始的任务继续运行，修正已有运行实例另定不打断任务的处理方式。

5. **还原位置和关注状态。** 将恢复终端正式接入原位置，确认窗口模型绑定的是新终端。根据新终端的轮次及当前状态迁移关注标记，保留原时间和顺序。写入前重读：用户在基线后产生的操作优先；不能用旧快照覆盖新工作。遇到 keep 退回 shell、临时借显、关注标记迁移或关闭行为，读取 [Core 恢复细节](references/herdr-core.md)。

6. **逐项验收并交付。** 对照基线的全部字段逐个核对；仅允许已记录的终端或 pane ID 映射、轮次重基和用户后续变更。用宿主 agent 工具读取恢复会话，确认原历史与可交互状态；元数据核对角色、父子关系及存活策略，当前 Herdr 窗口核对正式位置和关注分组，截图核对可见结果。后台子会话核对所属父级及可达入口。**每个目标均有证据支持“复用／已恢复／跳过／阻断”，才完成本轮。**

   返回各类数量、具体阻断、获准的替代及未验证项。只清理本轮辅助资源；恢复出来的会话是交付物。旧 shell 或旧终端的移除须先确认没有运行任务、未保存内容或仍依赖它的后代；关闭影响依据当前原生契约核实，不能用关闭工作会话来试验。
