# 送达

## 送达纠偏

用户同意后，对每个收件对象：

1. `hc get` 用会话记录核对身份（地址会变），`hc read` 看最新状态；草稿已经过期就先更新，再告诉用户。
2. 对象处于 blocked 时，先按下面的“代答提问”关掉对话框。否则 `hc send <t> "$msg"`：正文用 quoted heredoc 赋给 `msg`，开头写“[旁路审查，用户已确认]”。
3. 发送后用 `hc wait` 等。

完成标准：在对象的会话记录里查到这条消息、而且它已经开始处理，才报“已送达”；有没有生效留到下一轮核对。

## 代答提问

可以代答两类提问：用户已经裁决过的，以及能按账本和用户已有裁决回答的。两类在消息里分开写：用户裁决过的放在“[旁路审查，用户已确认]”下面；你按账本推出来的放在“[旁路审查代答]”下面，并写明依据哪一项账、哪一次用户裁决。这样以后建账时，不会把你的推论当成用户的话。

提问会排队弹出，关掉一道可能触发新一轮回复，这时发出的消息会丢。按下面的顺序：

1. `hc keys <t> esc` 关掉当前对话框，`hc wait <t>`，再 `hc read <t> --lines 0` 看屏幕。
2. 重复到屏幕上没有对话框为止。冒出一道会改变目标、范围或者不可撤回的提问，就停下，列进待决项转告用户。
3. `hc send --if idle <t> "$msg"`。消息写明这几道提问是替用户关掉的、以本条为准，并逐道给出回答。
4. 发送被拒就 `hc wait <t>`，然后看屏幕：有对话框回到第 1 步，没有就重发。

esc 只用来关对话框，对象还在运行时按 esc 会打断它。
